## شروع سریع

برای اجرا، به سرور دبیان یا اوبونتو با systemd، دسترسی SSH، ابزار `curl` و دسترسی root یا sudo نیاز دارید.

در ترمینال سرور، این **دستور تک‌خطی** را وارد کنید:

<div dir="ltr">

```bash
curl -fsSL https://raw.githubusercontent.com/Sir-Adnan/GRE-Tunnel-Manager/main/gre.sh -o gre.sh && sudo bash gre.sh
```

</div>

اگر با کاربر **root** وارد شده‌اید، بخش `sudo` را حذف کنید. فایل اسکریپت با نام `gre.sh` در پوشهٔ فعلی ذخیره می‌شود. برای اجرای دوباره، در همان پوشه دستور `sudo bash gre.sh` را بزنید. دریافت دوباره، همین فایل محلی را جایگزین می‌کند.

اگر ابزار دریافت نصب نیست، ابتدا دستور زیر را اجرا کنید؛ برای کاربر root، بخش `sudo` را حذف کنید:

<div dir="ltr">

```bash
sudo apt-get update && sudo apt-get install -y curl
```

</div>

نصب موتورهای اختیاری فقط هنگام تأیید راه‌اندازی مربوط انجام می‌شود.

## انتخاب بخش مناسب

| بخش منو | کاربرد |
| --- | --- |
| گزینهٔ ۱؛ تونل GRE | ساخت، نمایش و حذف تونل GRE و نوع سادهٔ آن |
| گزینهٔ ۲؛ فوروارد پورت | انتقال پورت با iptables یا nftables |
| گزینهٔ ۳؛ تونل HAProxy | مدیریت تونل TCP، لودبالانس، سرویس و لاگ |
| گزینهٔ ۴؛ تونل Realm | مدیریت تونل TCP و UDP و سرویس آن |
| گزینهٔ ۵؛ تونل معکوس | راه‌اندازی FRP یا rathole روی دو سرور |
| گزینهٔ ۶؛ لودبالانس | تقسیم ترافیک بین چند سرور |
| گزینهٔ ۷؛ ابزارها | وضعیت سرور، بازیابی، پاک‌سازی و راهنما |

هر ابزار منوی اختصاصی دارد و افزودن، نمایش، ویرایش و حذف در همان بخش هستند. شمارهٔ گزینه را وارد کنید و Enter بزنید. برای فوروارد مستقیم، ساخت GRE لازم نیست.

هدر، آی‌پی‌های سرور، نام میزبان، سیستم‌عامل و ارائه‌دهندهٔ شبکه را در دسترس نگه می‌دارد. آدرس عمومی و محلی جدا مشخص می‌شوند؛ اطلاعات ارائه‌دهنده تقریبی است و در نبود اینترنت، آدرس‌های محلی نمایش داده می‌شوند. برای تازه‌سازی، گزینهٔ **Tools → Refresh Server Info** را بزنید. روش غیرفعال‌کردن دریافت آنلاین در [راهنمای هدر](docs/TERMINAL-UI.md#اطلاعات-سرور-در-هدر) آمده است.

## ساخت اولین تونل هاپروکسی

1. ابتدا وارد **HAProxy Tunnel → Add Tunnel** شوید و **پورت ورودی**، مثلاً `443`، را وارد کنید.
2. سپس **آی‌پی مقصد** و بعد **پورت مقصد** را بدهید؛ واردکردن ترکیبیِ `IP:port` هم پذیرفته می‌شود.
3. در پایان، نگاشت را بررسی کنید و گزینهٔ **Save & apply** را بزنید.

نام تونل خودکار ساخته می‌شود و تغییر نام یا تعیین آی‌پی شنود اختیاری است. تونل‌های هاپروکسی و ریلم به‌صورت پیش‌فرض روی همهٔ آدرس‌های محلی IPv4 گوش می‌دهند. فوروارد کرنلی، آدرس محلی را از اطلاعات مسیریابی سرور انتخاب می‌کند؛ آدرس انتخاب‌شده پیش از اعمال نمایش داده می‌شود.

برای چند پورت، فهرستی مانند `443,8443` یا بازهٔ کوتاهی مانند `8000-8003` وارد کنید. سپس انتخاب کنید همه به پورت مقصد واردشده بروند یا شمارهٔ پورت خودشان را حفظ کنند. همهٔ نگاشت‌ها پیش از ذخیره نمایش داده می‌شوند و برای هر پورت ورودی یک مورد مستقل ساخته می‌شود؛ سقف هر راه‌اندازی ۳۲ پورت است. ویرایش موارد موجود، جداگانه انجام می‌شود.

## امکانات اصلی

- تونل‌های شبکه شامل GRE و ip6gre، با تنظیم MTU و حفظ سازگاری دو سمت هستند.
- فوروارد کرنلی، ترافیک TCP و UDP را بدون پردازش دائمیِ مدیر منتقل می‌کند.
- مدیریت هاپروکسی، بررسی اتصال مقصد، failover، زمان انتظار و وضعیت محلی را ارائه می‌دهد.
- مدیریت ریلم، انتقال TCP و UDP را فراهم می‌کند؛ تونل معکوس هم با FRP و rathole در دسترس است.
- تغییرات فوروارد پیش از اعمال بررسی می‌شوند و نقاط بازیابی خودکار دارند؛ حذف گروهی هم پشتیبانی می‌شود.
- رابط ترمینال انگلیسی، با رنگ‌بندی ثابت، هدر اختصاصی و انتخاب عددی طراحی شده است؛ تنظیم تم یا زبان لازم ندارد.

## نکات پیش از استفادهٔ اصلی

پورت‌ها و پروتکل‌های لازم را در فایروال سرور و ارائه‌دهنده مجاز کنید. تونل GRE به پروتکل شمارهٔ ۴۷ نیاز دارد و رمزنگاری ندارد. برای وایرگارد و AmneziaWG از فوروارد UDP استفاده کنید؛ هاپروکسی این پروژه فقط TCP را منتقل می‌کند. پیش از جابه‌جایی سرویس اصلی، یک پورت جدا را آزمایش کنید.
