# Interface conventions

Settings uses four route-backed tabs: Security & access (default), Appearance, Notifications and Metrics. Existing `section=notifications` and `section=metrics` bookmarks select their tab. Inactive panels stay mounted but hidden so unsaved integration fields are retained in memory while switching tabs. Mobile tabs use two columns and 44 px targets; desktop uses one row. Security begins with browser connection security: actual loaded-certificate metadata, a trust distinction, expiry and a fixed-path reload action. HTTP, self-signed HTTPS, panel-renewed Let's Encrypt and externally issued certificates have separate copy; panel-renewed certificates show the next renewal and a non-blocking notice after a failed attempt, and warn about expiry only when renewal is overdue. Certificate commands use the shared wrapping/copy component; keys/PEM never enter the UI. Server DNS labels active global servers and configured values separately and explains local stub addresses. Backup tabs explain off-server downloads, on-server scheduled snapshots and paused restore before their forms. Invalid advanced fields activate their owning controlled tab before focus/validity reporting. A saved connection's later policy failure closes the creation form with partial-success guidance so it cannot invite duplicate creation.

Backup & restore uses separate create/restore tabs and a source-to-destination review. Passwords and file contents stay in transient component/request memory, never route parameters or browser storage. IP/interface edits invalidate the current review until checked again. Show resource summaries, blockers and external-certificate references before a separate confirmation. A successful import explains the paused state and activation steps; partial accounting failure remains visible.

The browser is the interface; the Bash engine and the Go control layer own validation and system operations. Keep configuration and system operations outside UI components.

## Terminal (gtm)

`gtm` is the only terminal interface; `install.sh` only downloads and verifies, and the engine never prompts ([Command line](COMMAND-LINE.md)). Code lives in `panel/internal/gtm` (commands), `panel/internal/install` (system work, no UI) and `panel/internal/tui` (presentation).

- English only: SSH terminals rarely shape right-to-left text. Short sentences, sentence case, the action named in the answer.
- Every line is indented two spaces. A screen starts with a header (product, version, one-line subtitle) and a rule; status uses aligned label/value rows with a colored dot only where state matters.
- Progress uses four marks: `›` step, `✓` done, `!` attention, `✗` failure. Results that matter later (address, a generated password) go in one rounded card, shown once.
- Questions are Huh forms in the Signal palette: one question per form, the answer then stays above as a `✓` line so the wizard reads as a checklist. Esc or Ctrl+C cancels before anything changes.
- Body text keeps the terminal's foreground color; accents meet WCAG AA on dark and light backgrounds. `NO_COLOR`, pipes and `TERM=dumb` get plain text; `GTM_ACCESSIBLE=1` asks line by line.
- Every question has an option, so `--yes` or a missing terminal never blocks. Secrets come from hidden prompts, environment variables or root-only files, never from arguments `gtm` builds.

## Web panel

- Use the existing Radix/shadcn components and semantic tokens. **Signal** (Grafana-like) is the user-selected default preset; **Graphite** (Linear-like) and **Aurora** are project presets, and **Nettinx** and **Neutral** remain selectable. Project presets define every status and `*-text` token and must pass the WCAG AA pairs in `panel/web/tests/themes.test.mjs`. Nettinx source colors stay exact; its approved dark foreground override applies only to orange primary buttons, and its documented contrast limitations are not waived as passing checks.
- Typography is preset-independent: local Inter Variable sets Latin text and digits, Persian glyphs fall through to local Vazirmatn, and JetBrains Mono is reserved for addresses, ports and configuration. Persian keeps zero letter spacing and taller lines. Use Persian RTL/English LTR, Latin display digits and explicit LTR isolation for IPs, ports and code.
- Type scale (`styles/system.css`): five sizes as utilities, `text-caption` 12, `text-body` 14, `text-sub` 16, `text-title` 20 and `text-display` 28 px. Page titles use title on phones and display from `sm`; card titles use sub. Each size has its own line height, taller under `[lang="fa"]`. Compared numbers use tabular figures (tables, `dd`, `time`, LTR-isolated values and `.tabular`). Names that may be Latin in a Persian page use `.bidi-name`, so they follow their own direction and truncate at their end.
- Surfaces are layered: the page, then cards one step above it with a hairline drawn from the foreground (`--surface-line`), a soft shadow (`--elevation-card`) and, in dark mode, a faint top edge (`--surface-edge`). Cards, KPI tiles and list cards share the `surface` utility. These derive from each preset's own tokens, so preset colors stay exact.
- Density is a browser preference (`comfortable` default, `compact`) on the root element as `data-density`, so dialogs follow it. It changes `--card-pad`, `--card-pad-sm`, `--row-pad`, `--page-gap` and `--list-gap` only; type sizes and touch targets do not shrink.
- Connection state has one visual language (`lib/connection-tone.ts`): ok, warn, problem, off and pending, derived from the service state, health checks and firewall badges. The status chip (icon plus accessible name) and the route chain's wire carry it; the runtime status badge keeps its words and colors only its dot, so "active" is never shown in an alarm color. Ok means nothing known blocks the connection, never measured traffic.
- Phones (below 768 px, `hooks/use-mobile.ts`) get their own patterns in `styles/mobile.css`:
  - Every `DialogContent` is a bottom sheet with a grabber; dragging it down past a quarter of its height (at most 120 px) or flicking closes it through the dialog's own `onOpenChange`, so a busy dialog that refuses to close springs back. `mobileLayout="dialog"` keeps a dialog centred (only the command palette, whose input must stay above the keyboard). `Sheet side="bottom"` has the same grabber.
  - Row "more" menus use `components/ActionMenu`: one list of groups renders a dropdown on larger screens and an action sheet with 48 px rows on phones. New row menus should use it instead of composing `DropdownMenu` directly.
  - Connection cards are wrapped in `components/SwipeActions`. A touch swipe toward the reading start reveals **Turn on/off** and **Edit**; the other way reveals **More**, which opens the card's action sheet. Delete is never a swipe. Only touch starts a swipe, inputs keep their own gestures, a vertical move always scrolls, selection mode turns swipes off, and the revealed buttons are hidden from assistive technology because the card's own controls already offer each action. Thresholds live in `lib/gesture.ts` with tests.
  - Phone cards show checkboxes only in selection mode: the toolbar's **Select** starts it, a tap toggles a card, and the selection bar offers **Select all** and closes with its button or Esc. A long press is left to the browser, so names and addresses can be selected and copied; only selection mode makes a card unselectable as text.
  - Opening a dialog, sheet or form never raises the on-screen keyboard: on touch-first devices (`lib/focus.ts`, coarse and no fine pointer) `DialogContent` and `SheetContent` focus the dialog itself instead of its first field, and fields use `autoFocus={autoFocusField()}` instead of a bare `autoFocus`. Mouse and keyboard users still start in the first field. The command palette keeps its focused search box on purpose.
  - Narrow phones (below 26 rem, and 22.5 rem) lower the root font size to 15 and 14.5 px, so spacing, icons, the header and the bottom bar tighten in proportion. Phones whose system text or display size is enlarged also land here, because enlarging narrows the page. Text keeps a floor (`--text-xs`/`--text-caption` 12 px, `--text-sm`/`--text-body` 13.5 px in `styles/system.css`), inputs stay 16 px and touch targets 44 px.
  - The bottom bar keeps four pages and **More**, which opens a sheet with every other page, grouped as in the sidebar, after two quick actions (new connection, search and commands). A warning dot (with a screen-reader label) marks Overview when anything needs attention and Connections when a connection does. The bar slides away while reading down a page and returns on any clear move up, near the top, at the page end and while it holds focus; the selection bar follows it down.
  - The viewport declares `interactive-widget=resizes-content`, so the on-screen keyboard shrinks the layout and sheet forms keep their focused field visible.
- Reordering is a mode, not a permanent handle: a list that people order offers **Reorder**, which shows `components/ReorderList` until **Save order** or **Cancel** in a floating bar (the selection bar's place); moves stay local until saved, and the saved toast offers **Undo**. Only the connections list and the form's destination list (failover priority) are reorderable; dashboards and other card grids keep a fixed order. A sort other than the custom order switches back to it when reordering starts.
  - Every reorderable row has a position number (live while dragging, tinted once moved), a handle and a ⋯ menu built by `lib/move-actions.tsx` (top, up, down, bottom; entries that would not move are left out).
  - `components/sortable` drags at once from the handle with any pointer. In the reorder list, a touch press and hold (260 ms, 8 px tolerance) anywhere a row spreads `item.press` also picks it up with a short vibration, so a swipe still scrolls. Form rows (`SortableArea pressToDrag={false}`, the destination list) drag only from the handle, so a long press selects their text. Presses on buttons and fields stay theirs. On coarse pointers the handle moves to the row's far end, under the thumb.
- Routes in lists (`features/connections/RouteChain`) keep each IPv4 address and port whole; the only break is between the two (IPv6 may break anywhere). A connection card is a size container: below 26 rem its route stacks (listener, a short downward wire, destination) so the address gets the card's full width. A destination is a button: one address copies on tap (with a toast), several open a list where each address, or all of them, can be copied.
- Live per-connection speed (`features/traffic/live.tsx`, state in `use-live.ts`) comes from one provider per page polling `GET /api/metrics/live` every 2 s while visible (30 s while usage collection is off). `LiveRateBadge` shows down/up for one id and renders nothing without a rate. Received is the success color and sent the primary color on every traffic surface.
- Long forms are titled cards: `components/FormSection` (icon, title, one line, fields). A few exclusive choices that each need a line of explanation use `components/ChoiceCards` (a native radio group; `compact` makes one row per choice on phones); longer lists keep a select. A select's options hold only the value (an address or interface stays readable in both directions); a qualifier such as *main*, *suggested* or *no longer on this server* goes in a caption under the field, never as a suffix in the option, where bidirectional text reorders it and the chevron clips it. Every field label row has one height (`.field-label-row`), with or without a help button, so fields side by side line up.
- Field errors show under their field. `TextField` and `Choice` read their message from `FieldErrorsContext` (`lib/field-errors`) by input id, or take `error`; a form checks with the native constraints, fills the context with `validityMessage` and focuses the first field. Two or more errors, or one on a field without an inline message, add a summary at the top whose entries focus each field. No browser validity bubbles.
  - The connection form shows one destination as plain fields; two or more become numbered rows that open to edit (an incomplete row opens and stays open), with **Primary**/**Backup** marks when the method is primary + backup.
- Motion is subtle (about 150-260 ms, eased): page sections cascade in, cards lift slightly on hover, live indicators pulse and the selection bar rises. All of it lives in `styles/motion.css` and is removed under `prefers-reduced-motion`. Entry animations must not leave a transform behind (use `backwards` fill), or fixed descendants lose the viewport as their containing block.
- Keep common fields visible, advanced settings grouped in tabs and contextual help accessible by hover, keyboard and tap. Labels must describe the actual action: relative share is not priority; start after saving controls enabled state.
- Choose tables/cards by available content width. Separate IPv4/IPv6, keep labels beside values and show multiple destinations through accessible disclosure.

## Browser workspace

Hash routes (`#/connections?engine=haproxy`, `#/traffic?tab=details&resource=F000001`) support direct links and browser back/forward without server rewrites. `lib/navigation.ts` allowlists pages and maps the v1.3 engine pages (`#/forwarding`, `#/haproxy`, `#/realm`) to the Connections page with an engine filter; `use-panel-route.ts` owns URL subscriptions and rewrites legacy or unknown addresses to the canonical route in place.

Navigation has one model (`components/nav-items.ts`) shared by the sidebar, the mobile bar and the command palette: **Workspace** (Overview, Connections, Traffic), **Network** (Nodes, GRE, Reverse) and **System** (Engines, Backup & restore, Settings). Ctrl/Cmd+K, the sidebar search field, the mobile search button or **More → Search and commands** opens the command palette: pages, engine filters, creation per engine, appearance and saved connections. A saved connection opens a second step with its actions (details, check, edit, turn on/off, duplicate, configuration, delete); Backspace on an empty search or Escape goes back. Commands navigate, open forms or dialogs, or change local preferences; turning a connection on or off is the one direct operation, the same as the row's switch. Delete and configuration open the list's own dialogs through `remove=` and `config=` route parameters, so delete still asks for confirmation. Connection search, status and inspection tabs use query parameters. Replace history for filter typing; push history when opening a connection. Do not put configuration, credentials or tokens in URLs.

`PanelHeader` owns local-server identity, separately copyable addresses and appearance/language controls. Connection management is local; this header must not imply that arbitrary remote operations are available. Nodes separate the server inventory from coordinated connection setup.

The overview is status-first: host identity and one address, four KPI tiles (connections, running services, items needing attention, uptime/load), live telemetry beside a **Needs attention** panel and recent connections with engine shortcuts. `lib/attention.ts` derives attention items from inventory alone: enabled services in a failed or stopped systemd state, and engines that enabled connections need but that are not installed. An empty list is shown as an explicit healthy state.

`ConnectionWorkspace` owns list scope and the engine filter chips (`lib/connection-filters.ts`, with counts); a filtered view also chooses the engine a new connection starts with. `ConnectionTable` owns selection and revision-bearing actions; names open a read-only detail dialog. Each row has an explicit on/off switch and edit; details, configuration, logs and delete use a labeled menu. Bulk actions appear in a floating selection bar (portaled to `<body>`) only while rows are selected, above the mobile navigation on phones. Mobile identity and engine metadata are distinct stacked elements. Balance desktop column widths instead of giving every spare pixel to the name. Search/status filters share a compact row when they fit. The whole-server preview belongs in the toolbar. Do not replace actual runtime status with optimistic health claims.

Configuration imports separate file/text entry from parsed resource review. Show replaced process settings, activation state and generated output before saving. Any draft edit invalidates review. Engine maintenance displays installed, upstream and verified/candidate versions separately; checking is read-only, updating requires its own confirmation. The header's appearance button opens one popover with the color mode and the preset list. Settings shows presets as cards with light and dark miniatures painted from registry swatches, default first.

`useConnectionDraft` retains a private copy of the opened record. `ConnectionBasics`, `ConnectionAdvanced` and `ConnectionReview` render distinct stages. Required ports precede optional names; desktop entrance/destination panels stack on mobile. Tabs retain their controls so hidden invalid fields are revealed and focused before review. Network validation and mutations remain authoritative on the server.

Changed connection, GRE/reverse and configuration drafts use `use-discard-changes` for close/refresh protection; unchanged views close immediately. Drafts remain in memory and are not saved in browser storage. Successful save bypasses discard confirmation. Sonner notifications distinguish success, failure and a completed mutation whose inventory refresh failed. Mobile notifications sit above bottom navigation. Use concise visible errors; help tips must never hide essential failures or destructive-action warnings.

## Modal layout

Long dialogs use `DialogContent scrollLayout="body"` with one `DialogBody` between fixed header/footer siblings. The body must establish a positioning context and prevent direct children from shrinking. `Field` also establishes a positioning context: Radix hidden absolute form inputs can otherwise extend the outer scroll area beyond visible content.

Use `DialogFooter layout="summary"` for a route summary followed by action buttons. Its mobile order is explicit; do not override the standard action footer's reversed column layout through competing utility classes.

Use `FieldGroup columns` for two desktop columns and one mobile column. Code/installer blocks keep intrinsic height, wrap within narrow layouts and remain manually selectable. Avoid nested vertical scrollers.

Copy actions share `lib/clipboard.ts`: prefer the Clipboard API, then attempt a user-initiated selection copy for HTTP or denied API access. Temporary fields stay inside the active modal to respect its focus trap, are removed after copying and restore focus/selection. Only report success after an API confirmation; otherwise show a bilingual manual-copy instruction. Never put enrollment codes, tokens or configuration contents in notifications.

## Frontend modules

- State: `lib/use-session.ts`, `lib/use-inventory.ts` (load and optional 30 s refresh, paused during jobs), `lib/use-operations.ts` (job runner and result dialog) and `lib/preferences.ts` (validated, migrated browser preferences). `App.tsx` composes them.
- Polling: every periodic request uses `lib/use-poll.ts`, which runs only while the page is visible, never overlaps runs, aborts on hide, unmount or timeout and always calls the latest callback.
- Messages: `lib/i18n/messages/<feature>.ts` hold `[English, Persian]` pairs checked by `satisfies Messages`; a key lives in exactly one module and Persian text uses Latin digits (`tests/i18n.test.mjs`). Shared words live in `common.ts`.
- Errors: show a thrown value with `errorMessage(e)` from `lib/i18n` (or `errorText(e, t)` where `t` is a prop). It translates the panel's own server sentences through the catalogue in `lib/server-messages.ts` and leaves engine reports as they are; operation failures that a person must act on use `components/ErrorExplain`. A new server sentence shown to people gets a catalogue entry and an `srv*` message; `tests/server-messages.test.mjs` fails when a catalogued sentence disappears from the Go sources.
- The document root carries the interface language and direction (`App.tsx`, set before paint), so `[lang="fa"]` typography, screen-reader language and portalled dialogs follow the preference. Never hard-code `lang` or `dir` on an inner wrapper to change the page language.
- Styles: `index.css` only imports; `styles/base.css` (fonts, document defaults, elevation), `system.css` (type scale, surfaces, density), `shell.css` (sidebar, header, mobile bar), `components.css` (patterns), `operations.css` (health and maintenance), `firewall.css` (the Firewall and IP addresses pages, which share pills, chips and the side sheet), `forms.css` (dialogs and editor), `mobile.css` (bottom sheets, action sheet, swipe cards, bottom-bar states) and `motion.css`. Colors come only from style tokens.
- Preferences migrate once from `gtm.preferences.v1` to `v2`. v1 always stored the style, so its stored Nettinx (the old default) becomes Signal; any choice saved afterwards, Nettinx included, is kept.

## Verify interactions

Check actual geometry, not just document overflow: no excess outer modal scroll, visible actions and a reachable final input. Test both locales, light/dark, narrow mobile and wide desktop. Exercise selection, switches, presets, review/apply and traffic actions in the loopback demo. Missing samples remain unavailable; never substitute zero or sum overlapping GRE/forward counters.

See [Development](DEVELOPMENT.md) for automated checks and [Releasing](RELEASING.md) for publication gates.

Dashboard activity uses one compact four-metric region with Latin values and directional network labels. A pause control and 5/15-second cadence keep polling explicit. Unavailable readings use a dash, never a fabricated zero. Quota presentation shares `QuotaStatus` between mobile rows, desktop cells and details; show the numeric cap, current usage/direction and the last successfully applied blocking status. Automatic pause is opt-in with sampling, scope and resume help.

Destination cards separate reorder/index/remove controls from the editable field grid. Below a 30 rem card width the address spans the whole row and port/share sit side by side; wider cards align all three controls. Shared text/choice label rows reserve the same height, including optional help. Connection rows and cards show the route as one chain (entrance, wire, destinations) with screen-reader labels for the listener and destination; on narrow cards the destination wraps below the entrance. Host/port values can wrap at their boundary, while a port stays intact; long IPv6/domain values can wrap. Do not reduce input text below 16 px on phones or disable browser zoom to compensate for a layout problem. CSS text-size-adjust controls automatic inflation while preserving user zoom. Optional background help uses the shared hover/focus/tap `HelpTip`; errors, current state and destructive consequences remain visible.
